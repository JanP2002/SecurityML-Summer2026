## Overview

This chapter implements and analyses a series of **binary anomaly detectors** of
increasing sophistication.  The central question is:

> *Can a supervised classifier trained on known attacks generalise to completely
> unseen attack types?*

Two datasets are used in parallel throughout:

| Dataset | Resolution | Source |
|---------|-----------|--------|
| MNIST | 28×28 px grayscale | Public (LeCun et al.) |
| Pythia *(hidden)* | 70×70 px grayscale | Provided archive (`./pythia/`) |

## Contamination methods — `attacks/contamination.py`

The shared library implements all five methods from the task specification plus
OOD replacement:

### 1. Gaussian noise (additive)

$$\tilde{x}_{i,j} = \text{clip}(x_{i,j} + \varepsilon_{i,j},\; 0,\; 1), \quad \varepsilon \sim \mathcal{N}(0,\, \sigma^2)$$

Default: σ = 0.4.  About 32 % of pixels reach the clip boundary.

```python
from attacks import make_gaussian_attack
ds = make_gaussian_attack(images, std=0.4)
```

### 2. Salt & pepper noise

$$\tilde{x}_{i,j} = \begin{cases} 0 & u < p/2 \\ 1 & u > 1-p/2 \\ x_{i,j} & \text{otherwise} \end{cases}, \quad u \sim U(0,1)$$

Default: p = 0.15 (15 % of pixels corrupted).

```python
from attacks import make_salt_pepper_attack
ds = make_salt_pepper_attack(images, prob=0.15)
```

### 3. Geometric distortion

A smooth random dense deformation field is generated at a low resolution and
bilinearly upsampled to full image size, then applied via `F.grid_sample`:

$$\tilde{x}(p) = x(p + \delta(p))$$

where $\delta(p)$ is a smooth displacement bounded by `max_displacement` pixels.

```python
from attacks import make_geometric_attack
ds = make_geometric_attack(images, max_displacement=5.0)
```

### 4. Blended attack

$$\tilde{x} = (1 - \alpha)\,x + \alpha\,P, \quad \alpha \in [0,1]$$

$P$ is a fixed pattern (random noise by default).  Using a consistent
pattern across the dataset makes this a systematic (not random) contamination.

```python
from attacks import make_blended_attack
ds = make_blended_attack(images, alpha=0.30)
```

### 5. Backdoor trigger

A small bright square of side `trigger_size` is inserted at a fixed location
(`bottom_right` by default):

```python
from attacks import make_backdoor_attack
ds = make_backdoor_attack(images, trigger_size=5, position="bottom_right")
```

### 6. OOD replacement (no pixel transform)

Images from a structurally different distribution are re-labelled as attacks.
MNIST uses Fashion-MNIST clothing images as OOD samples.

```python
from attacks import make_ood_attack
ds = make_ood_attack(fashion_mnist_images)
```

## ProfessorCNN — configurable architecture (Steps 1, 2, 3 — Pythia only)

The `ProfessorCNN` is a configurable binary classifier designed by the instructor
for the **Pythia 70×70** dataset.  A 15-experiment staged hyperparameter search
(`step_professor_search.py`) selects the best configuration, which is then loaded
automatically by `get_professor_cnn_best(input_size=70)` in steps 1–3.

```
Input: (B, 1, H, H)

Block i (×3):  Conv2d(ch_{i-1}→ch_i, K×K, padding='same') → Activation → Dropout2d(p) → MaxPool2d(2,2)
  channels = [32, 64, 128]  (default)
  K         = {4,5} × {4,5} kernel (searched)
  Activation = LeakyReLU(0.01) | SiLU (Swish) | GELU  (searched)
  Dropout rate p  ∈ {0.1, 0.2, 0.3}  (searched)

Pooling: GlobalAvgPool2d  OR  Flatten  (searched)

Dense head (×2):  Linear(in→d_i) → Activation → Dropout(p)    d_i ∈ {[128,64], [256,128], [64,32]}  (searched)
Output:           Linear(d_last→1) → Sigmoid

Output: ŷ ∈ (0,1)  —  P(anomaly)
```

Loss: Binary Cross-Entropy | Optimiser: Adam lr=0.001 | Search: 15 experiments across 3 stages

**Search stages:**

| Stage | Experiments | Variables fixed | Variables searched |
|-------|-------------|-----------------|--------------------|
| 1 | 6 | dropout=0.2, head=[128,64], pool=global_average | kernel∈{(4,5),(5,5)} × activation∈{leaky_relu,swish,gelu} |
| 2 | 3 | best kernel+activation, head=[128,64], pool=global_average | dropout∈{0.1,0.2,0.3} |
| 3 | 6 | best kernel+activation+dropout | head∈{[128,64],[256,128],[64,32]} × pool∈{global_average,flatten} |

Selection criterion: **validation AUC-ROC** (maximised).

If `faza_professor_cnn_search.json` does not exist when a step runs,
`get_professor_cnn_best()` falls back to the default config and prints a warning:

```
[ProfessorCNN] Search results not found at '...faza_professor_cnn_search.json'.
  Run 'python step_professor_search.py' first to select the best variant.
  Proceeding with default config.
```

The default config is `kernel=[5,5]`, `activation=gelu`, `dropout=0.2`,
`head=[128,64]`, `pool=global_average`.  See [HYPERPARAMS.md](HYPERPARAMS.md)
for the full hyperparameter reference.

## Step 1 — Supervised baseline (closed-world)

**Research question:** Can a CNN trained on `clean` + `attack_a` detect
a completely different `attack_b`?

**Setup:**

- Model: `AnomalyCNN` — 3-block CNN with MaxPool, BCE loss, Adam (lr=0.001)
- Training: `clean ∪ attack_a` (balanced 50/50), up to 15 epochs, early stopping patience=3
- Test_A: `clean_test ∪ attack_a_test` (known attack)
- Test_B: `clean_test ∪ attack_b_test` (unknown OOD attack)

**Expected result:**

- Test_A: Accuracy, F1, AUC-ROC all close to 1.0
- Test_B: Severe degradation, especially Recall and AUC-ROC

This demonstrates the **closed-world assumption failure**: the classifier
learned a noise-specific boundary, not a model of normality.  When the
OOD attack does not activate the learned noise-sensitive filters, it is
misclassified as clean.

## Step 2 — Generalisation via multi-attack training

**Research question:** Does training on more diverse attack types improve
detection of a completely unseen attack $A_{n+1}$?

**Setup:**

For each round $n = 1, 2, \ldots, K-1$:

1. Training set: `clean ∪ balanced_sample(A_1, …, A_n)` — kept at 1:1 ratio by
   subsampling each attack type to `len(clean) // n` samples.
2. Test set: `clean_test ∪ A_{n+1}` — the $(n+1)$-th attack is never seen during training.
3. Fresh `AnomalyCNN` trained from scratch for each round.

**MNIST attack sequence:**

| Index | Name | Method | Key param |
|-------|------|--------|-----------|
| A1 | `A1_gaussian` | Gaussian noise | σ = 0.4 |
| A2 | `A2_salt_pepper` | Salt & pepper | p = 0.15 |
| A3 | `A3_geometric` | Geometric distortion | max 5 px |
| A4 | `A4_blended` | Blended attack | α = 0.30 |
| A5 | `A5_backdoor` | Backdoor trigger | 5×5 px |
| A6 | `A6_ood` | OOD (Fashion-MNIST) | — |

**Pythia** uses all 8 labelled partitions (`attack_a` … `attack_h`), 7 rounds total.

**Output:** `plots/step2/` contains five figures showing all 5 metrics
(Accuracy, Precision, Recall, F1-Score, AUC-ROC) as a function of $n$ for both datasets.

## Step 3 — Unsupervised autoencoder anomaly detection

**Research question:** Does an autoencoder trained *only on clean data* detect
a completely unseen attack better than the supervised Step 1 classifier?

**Key idea:** The classifier of Step 1 learns to recognise one specific attack
(attack_a = Gaussian noise).  It therefore fails on a structurally different
unseen attack (attack_b = OOD Fashion-MNIST).  An autoencoder takes the
opposite approach: it is trained only to compress and reconstruct **clean**
images, so its reconstruction error naturally flags anything off the clean
manifold — with no prior exposure to any attack.

**Setup:**

Both detectors are trained on identical data splits for a fair comparison:

| Detector | Training data | Anomaly score |
|---|---|---|
| `AnomalyCNN` (Step 1) | clean ∪ attack_a | sigmoid output ∈ [0,1] |
| `ConvAutoencoder` (Step 3) | **clean only** | reconstruction MSE ∈ [0,∞) |

The autoencoder threshold is the **95th percentile** of reconstruction error
on a held-out clean validation split — chosen without ever looking at attack
data, preserving unsupervised status.

**Extended analysis:** both trained detectors are also evaluated on every
contamination type (MNIST: all 6; Pythia: all 8), without retraining.  This
shows which anomaly families each paradigm can and cannot detect.

**Hyperparameters:**
- Autoencoder: 30 epochs max, patience = 5, latent_dim = 32, random seed = 42
- Classifier: 15 epochs max, patience = 3 (identical to Step 1)

## Model architectures

### `AnomalyCNN` (Steps 1 & 2)

```
Input: (B, 1, H, H)

Block 1:  Conv2d(1→16,  3×3, pad=1) → ReLU → MaxPool2d(2,2)
Block 2:  Conv2d(16→32, 3×3, pad=1) → ReLU → MaxPool2d(2,2)
Block 3:  Conv2d(32→64, 3×3, pad=1) → ReLU → MaxPool2d(2,2)

Flatten → Linear(flatten_size → 128) → ReLU → Linear(128 → 1) → Sigmoid

Output: ŷ ∈ (0,1)  —  P(anomaly)
```

Loss: Binary Cross-Entropy | Optimiser: Adam lr=0.001 | Threshold: τ = 0.5

### `ConvAutoencoder` (Step 3)

Encoder–decoder with the same channel progression as `AnomalyCNN` (1→16→32→64,
then 128-unit hidden layer) so the encoder can be reused as a feature extractor
in Step 4.  All conv and hidden-FC layers use BatchNorm + LeakyReLU to prevent
collapse on sparse data (MNIST pixels are ~87% black).

```
Encoder  g:  Conv(1→16)+BN+LReLU+MaxPool  ×3  →  Flatten  →  FC(→128)+BN+LReLU  →  FC(→32)
Decoder  f:  FC(32→128)+BN+LReLU  →  FC(→flat)+BN+LReLU  →  reshape
             Upsample×2 + Conv(64→32)+BN+LReLU  ×3
             interpolate(input_size)  →  Conv(8→1)  →  Sigmoid
```

Anomaly score: $s(x) = \frac{1}{CHW}\sum(x - f(g(x)))^2$ (mean MSE per pixel)

Loss: MSELoss | Optimiser: Adam lr=0.001 | Threshold: 95th-percentile of clean-val errors

| H | H after 3× MaxPool | flatten_size | latent_dim |
|---|-------------------|-----------|-----------|
| 28 (MNIST) | 3 | 576 | 32 |
| 70 (Pythia) | 8 | 4 096 | 32 |
